## 3. ② 任务生命周期收口到 TaskService

### 3.1 改前

- 状态事实源：`state/tasks/*.json`（FileTaskStore）——**已是唯一**。
- 但生命周期语义有两套：
  - `server.py`：自己 `TaskRecord(...)` + `TASKS.save` + `mark_task` + `finish_task` + `recover_tasks` + `Popen` + `communicate(timeout=...)` + `PROCS`。
  - `application/tasks.py::TaskService`：自己的 `_open/_execute/cancel/recover`，生产零调用（只有 `checks/test_task_service.py` 用）。
- `JOBS` 已是视图（`_job_view`），不是第二份状态。

### 3.2 改后

```
ReviewApplication（v1 流水线）
        ^
        | runner(target, review_id=..., token=...)
TaskService（唯一生命周期：创建 / 幂等 / QUEUED→RUNNING / 完成 / 失败 / 取消 / 超时 / 恢复）
        |
        v
server._SubprocessRunner  ──►  subprocess.Popen(review.py …)  ──►  outputs/ + ledger/
        |
        └── JOBS（仅前端视图）、PROCS（进程句柄）
```

- `TaskService` 新增 `start_review_with(runner, ...)` / `start_async_with(runner, ...)`；现有 `start_review` / `start_async` 签名与行为不变（内部委托）。
- `server._SubprocessRunner` 实现 `Runner` 协议：把「这一次怎么跑」（research / type / scenario / 格式要求 / purpose / 进度文件）封在 runner 里，**进程隔离保留**。
- `_watch_cancel`：TaskService 置位令牌后 `terminate`，10 秒不退再 `kill`；超时与取消共用同一个令牌，不存在第二个超时实现。
- `_run_review_job` 只起进程、盯令牌、返回 `TaskOutcome`；**不再写任务记录**。
- `_start_review`（异步）与 `/api/review`（同步兼容口）都走 `TaskService`；`_cancel_review` 走 `TaskService.cancel`；`_recover_jobs` 走 `TaskService.recover`。
- `server.py` 中 `finish_task` / `mark_task` / `recover_tasks` 的引用数：**0**。

### 3.3 迁移路径与退出条件

- 迁移路径：`server` 只保留「参数校验 + 闸门 + 视图」，执行由 Runner 适配；后续若换成进程内执行，只替换 Runner 实现，TaskService 与路由不动。
- 第二套状态：**不存在**。`JOBS` 只读任务记录生成视图，进程重启后以 `state/tasks/` 为准；已通过 `_recover_jobs` 验证。
- legacy 退出条件（未到，不在本轮执行）：`--engine shadow` 累计 ≥ 20 个真实样本、连续 7 天零未解释差异 + 两条 ledger 校验全绿 + 回滚演练通过；之后才允许删除 `run_one` 运行入口。
